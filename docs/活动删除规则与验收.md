# 活动删除规则与验收

## 谁可以删除

| 身份                         | 删除范围与状态                                           |
| ---------------------------- | -------------------------------------------------------- |
| 活动删除管理员               | 授权范围内任意状态的活动，默认配置管理员获得全公司范围   |
| 发起者                       | 本人发起，且处于草稿、待补充、已撤回、已拒绝或已取消状态 |
| 审批中或执行中的发起者       | 先撤回或完成取消，再删除；已归档由管理员处理             |
| 其他审批人、执行人、部门成员 | 不能仅凭参与或查看资格删除他人活动                       |

新增权限 `activity:delete`（本人符合状态的活动）和 `activity:delete:any`（该角色数据范围内任意状态）。服务端同时检查有效身份、同一角色的数据范围、活动归属和状态；管理员拥有独立“活动删除管理员”角色，具有活动列表入口和全公司活动查看、删除能力，敏感内容授权继续单独控制。

## 页面操作

- PC活动列表操作列：查看 / 删除；不符合条件时不显示删除。
- 移动端活动卡片：查看与删除为独立入口，点击删除不会跳转详情。
- 活动详情：当前活动的操作区提供删除入口。
- 删除弹窗展示活动名称和编号，说明影响，要求填写5至500字原因；确认按钮提交时重新核对权限。
- 成功后列表刷新并处理末页空页；详情回到已授权活动列表。版本变化时关闭旧确认并刷新，防止按旧状态误删。

## 删除方式与外键报错

采用逻辑删除，新增主表字段 `deleted_at`、`deleted_by`、`deletion_reason`，并在活动JSON中保留删除信息。业务列表、导出、工作台、待办及领导看板排除已删除活动；详情、附件访问、审批办理及公开评价使用统一活动读取入口拒绝已删除主单。

一次事务同时完成：锁定当前配置及活动、验证版本与删除资格、取消所有待处理任务、使等待与活动节点失效、记录删除原因与操作者、标记主单、关闭公开问卷、停止待投递提醒并标记既有通知。已经完成的审批意见、附件、档案及评价原样保留。

直接执行 `DELETE FROM activities` 会触发1451错误，因为 `workflow_edges`、`workflow_nodes`、`workflow_tasks`、`files` 等仍通过外键引用该活动。系统删除保留关联结构和主记录，通过逻辑标记实现业务移除，因此无需手工拆删子表或关闭外键检查。

本期提供逻辑删除，不提供回收站或恢复页面。已有模板仍保留历史引用，不能通过删除活动绕过模板历史保护。

## 接口与并发

`DELETE /api/activities/:id`

请求字段：`expectedVersion`、`reason`、`idempotencyKey`。复用登录会话、来源验证及CSRF校验。请求和活动版本均在事务锁内检查；重复网络请求使用同一幂等键返回原成功结果，避免多次删除。异常时全部回滚。

## 验收要点

1. 发起者可删除本人上述五种状态，不能删除他人活动或本人审批、执行、归档中的活动。
2. 管理员可删除授权范围内的任意状态；账号停用或角色撤销后不可删除。
3. 隐藏按钮、修改活动ID、伪造发起者或使用另一个角色的全公司查看范围，均不能绕过删除授权。
4. 删除原因、版本或幂等键无效时拒绝；确认后若活动状态已变化，返回版本冲突。
5. 删除后所有列表、导出、看板、通知和待办不再展示该活动；旧详情、附件及问卷链接不可访问。
6. 审批流程停止，既有已完成意见保留；重复提交只处理一次；关闭评价等任一步失败，主单、任务与问卷整体回滚。
7. 删除功能迁移仅补充字段与默认权限，不删除实际活动、不重置密码、不覆盖未发布草案。

## 安装

`pnpm db:migrate` 或新库 `pnpm db:init` 会安装第五版结构与默认删除权限。迁移完成后刷新登录身份即可取得新按钮。已删除主单保留在数据库中，供审计和后续归档保留策略使用。
