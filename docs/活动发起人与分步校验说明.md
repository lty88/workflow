# 活动发起人与分步校验

## 发起人记录和展示

- 创建草稿时，发起人ID和部门由真实登录会话确定，同时将姓名快照存入活动JSON，前端不允许指定或改写发起人。
- 新活动后续改名不会影响发起时姓名展示；复制活动时重新使用当前账号作为发起人。
- 历史活动原本已记录发起人ID，未保存姓名快照的记录继续从成员配置解析姓名，无需人工补数据或执行数据库结构迁移。
- PC活动列表新增“发起人”列，手机卡片和近期活动展示姓名；详情及导出也包含发起人。

## 配置中心入口

原重复来源为动态菜单中的配置中心和管理员固定入口同时渲染。现在桌面端和移动端共用去重后的菜单，动态配置中心统一进入 `/settings`；已有入口时不再追加固定入口，没有分配动态配置入口的配置管理员保留固定入口。

菜单按页面组件识别，不按名称删除其他页面；已授权动态页面的顺序、名称、分组和权限保持原定义。

## 分步校验

1. 基础信息“下一步”：验证活动类型、当前可用模板，以及当前可见基础字段；包括名称、开始结束时间、举办方式、地点或线上会议链接等。
2. 内容与预算“下一步”：验证内容、人数、联系方式、自定义动态字段及费用；收费培训要求等依赖基础信息的规则使用完整表单上下文。
3. 顶部步骤条同样校验前置步骤，不能跳过未填写的基础或内容信息直接进入提交页。
4. 错误出现后停留在对应步骤，提供汇总、字段内红色反馈及滚动定位；修正后更新当前步骤错误，后续步骤不提前报错。
5. 后退不强制校验；保存草稿仍允许业务必填项暂缺。计算路线和提交前再次校验当前完整可填写内容，服务端提交时继续执行完整表单与权限校验。
6. 隐藏字段不阻塞步骤；受限占位信息保留展示，由服务端使用真实原值完成校验。操作中及提交结果待确认时禁止切换步骤。

验收重点：空名称不能进入第二步；基础信息完整时不会被未填联系人阻止；收费培训的要求在第二步提示；结束早于开始、无效链接、人数、联系方式及新增必填字段均在所属步骤提示；点击顶部第三步与下一步遵循同一规则。
