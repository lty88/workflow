# 执行指派与归档职责

有审批的活动采用同一条责任链：最后实际通过审批的人指派执行人；执行人持续记录、确认完成、提交成果归档；同一位最后审批人审核归档，退回后仍由执行人补充再提交。

## 最后审批人的认定

以本次申请轮次、当前节点代数的实际通过记录为准，排除历史申请、已跳过及已失效节点，不依据节点名称、画布位置或数组顺序。会签和并行审批，以最后实际通过的办理人为后续负责人；审批后还有任务或知会时，任务及知会不会覆盖审批职责。

新流程明确记录最后通过任务、负责人及审批节点；历史主单缺少字段时，详情与待办均按已通过任务的办理时间计算，同一时间使用稳定任务ID。正常保存业务操作时持久化结果，不批量改写历史活动。

## 权限与自审

终审人凭本活动的实际审批责任办理执行指派和归档复核，不再要求额外配置通用协调人或归档管理员角色。仍需账号、组织启用、活动可访问且保有审批办理权限。其他管理员、协调人或归档管理员不会因为通用角色取得该活动的指派与审核入口。

终审人不能把活动指派给自己执行，以免后续归档自审。前端执行人选项与服务端同时检查。执行人的归档提交、附件上传、被退回后的补充、待办和进度提示统一使用执行身份。

纯任务、纯知会等无生效审批的模板保持流程协调人指派、独立归档岗位审核，避免不存在最后审批节点时无法继续办理。有审批但办理记录不完整时不会回落到管理员。

## 既有活动

待归档审核的旧活动读取时使用真实最后审批人，已完成归档的审核人及历史记录保留。未提交的旧附件仍按原表单分组隔离，不扩大阅读范围。

现有通知记录保留；后续业务变更将向新的正确负责人发通知。无需数据库结构迁移。
