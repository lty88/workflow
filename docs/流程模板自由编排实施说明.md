# 流程模板自由编排实施说明

## 本次业务规则

此前“所有模板必须有部门负责人初审”的预设已经取消。开始是系统触发标记，首个业务节点没有固定类型。配置管理员根据活动场景选择审批、任务、知会，也可以组合多种类型。

默认按自上而下展示，可切换横向。执行顺序以箭头和前置依赖为准；拖动位置只调整布局。多个没有前置的业务节点同时开始，多个阻断前置全部完成后进入后继。

| 类型         | 谁办理               | 到达后行为                           | 是否阻断                 |
| ------------ | -------------------- | ------------------------------------ | ------------------------ |
| 系统开始     | 系统                 | 提交活动时启动无前置节点             | 系统标记，无个人待办     |
| 审批         | 节点受理人           | 同意、退回或拒绝；多人全员同意才通过 | 是                       |
| 任务         | 节点受理人           | 提交完成结果；多人全部完成才继续     | 是                       |
| 知会         | 系统通知配置的收件人 | 自动完成，写入可靠通知队列           | 否                       |
| 流程办理完成 | 系统                 | 所有生效审批及任务完成后进入待指派   | 系统标记，不代表活动归档 |

没有审批的任务模板：任务全部完成后进入待指派。纯知会模板：提交后通知并进入待指派。设计器与申请模板选择处均明确展示这些规则。若条件使全部节点被跳过，服务端阻止提交，要求调整模板或条件。

知会不作为人工关卡。配置“审批 A → 知会 B → 任务 C”时，B、C 都在 A 完成后触发。知会节点保留完成记录供资料权限和流程追溯使用，不产生待处理任务；通知按既有投递机制重试。

## 管理员操作

1. 新建流程模板，选择首个业务节点类型。
2. 进入设计器后，可修改该节点的名称、类型、受理人、条件、前置及数据权限；也可删除后重新添加。
3. 选中系统开始可添加节点；选中业务节点可前插、后插或并行新增。选中系统完成显示完成条件说明。
4. 业务节点支持工具栏删除、属性区删除、Delete / Backspace 与撤销。系统标记不参与删除或拖动。
5. 保存草稿允许暂时没有节点；检查和发布要求至少一个合法业务节点。
6. 发布前检查受理权限、部门范围、禁止自审、条件和依赖环路；发布后产生独立新版本。

## 旧模板和历史兼容

- 旧模板草稿在读取和保存时自动移除旧的 `protected` 默认锁定标记，受理规则、依赖及敏感资料权限保持原值。
- 已发布版本和已提交活动的定义快照不回写；要让新活动采用调整后的规则，需要发布新版本。
- 原公司配置兼容入口保留原校验，独立流程模板采用自由编排规则；因此不需要修改数据库结构或批量更新历史记录。
- 系统开始和完成仅作为图上边界，不保存为业务节点，不创建个人待办。

## 验证范围

静态类型、Vue 解析与结构检查；内存事务下调用真实创建、发布、提交服务，验证三种首节点、任务等待、纯知会自动完成及通知入队。所有局部校验均不连接真实数据库。
