# 站内通知轮询与声音提醒

## 使用

声音默认开启意愿按账号保存。登录后首次点击或键盘操作页面时自动启用提示音和中文语音，顶部直接显示声音状态；也可点击“启用声音”或在消息抽屉试听、静音、分别设置提示音和语音。主动静音会保留，后续点击不会强制重新开启。播报仅包含新消息数量，不朗读活动名称或内部资料。

首次进入只加载最近100条消息，不播报历史；打开抽屉会刷新已读状态，点消息标记已读并进入对应活动。新消息增量分页补拉，每页100条，因此不受抽屉展示100条的限制；角标统计当前展示消息中的未读数。

浏览器首次播放需要用户交互。刷新保留声音设置，首次点击自动恢复，无需每次进入消息抽屉重新设置。尚未激活或播放失败的新消息进入待播，恢复后自动补播，已读消息移出待播。页面或浏览器关闭后停止轮询和播报；后台降低轮询频率，浏览器节电可能延迟执行。声音功能未接入外部语音服务。

## 实现

- 复用现有10秒事务发件箱投递。前端可见时每10秒轮询；后台每30秒，恢复可见或网络时立即补拉。通知到达包含发件箱与轮询两段延迟。
- GET /api/notifications/feed 使用时间与通知标识组成游标，首次读取最近消息作为静默基线，后续按时间与标识升序补拉。
- 每个账号只读取本人收件箱，接口重新检查活动访问权限并过滤已删除活动；无权候选也推进游标，避免阻塞。
- 请求串行，单轮最多5页，仍有积压则500毫秒后继续；失败保留游标，指数退避至最长60秒。
- 账号切换、退出、卸载取消请求和定时器，迟到响应按会话代次丢弃。当前音频资源随会话退出关闭，账号偏好保留。
- Web Audio 生成短提示音；Speech Synthesis 播放中文数量提示。无语音能力时可单独使用提示音。
- 浏览器支持 Web Locks 时使用同源锁串行播报；局域网HTTP等不支持时使用短租约，后台页也可提醒。播放成功后才登记本地通知标识，失败不会提前去重。不在本地保存消息标题或正文。
- 顶部提供声音启用、错误重试入口，语音与提示音独立工作；账号切换取消旧语音并清空旧待播。
- 普通页面点击自动激活，声音设置控件由其自身点击处理，避免同一次点击先自动开启又误关闭。
- 不新增数据库表，不使用 WebSocket 或 SSE，不改变原有通知投递及审批规则。

## 校验

仅执行静态检查和局部测试。覆盖同毫秒多页补拉、实时数据权限、非法游标、历史静默、新消息去重、账号切换隔离和断网重试。新增音频接口替身局部用例覆盖首次点击自动激活、失败补播、刷新偏好、静音、多页去重、HTTP后台、已读清理与账号切换。遵循项目规则，本次不启动浏览器预览。

浏览器播放策略依据：[Chromium 自动播放说明](https://www.chromium.org/audio-video/autoplay/)。
