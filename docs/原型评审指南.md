# 活动流程 ERP 原型评审指南

日期：2026-10-21 · 版本：V0.1

## 动态流程新增评审入口（V0.2）

打开“活动流程ERP-动态流程图.html”，或在原型顶部点击“流程全景”。可切换标准办理、审批中加签、审批与筹备并行、执行中追加任务四种场景。点击环节查看前置和后继，使用“新增环节／子流程”选择前插、后插或并行，并模拟完成环节以观察后续激活。

这是独立的流程结构设计演示，数据与原工单办理分开保存。新版业务要求见《动态流程设计 V0.2》，下文保留原串行办理原型的评审路线。

## 打开方式

双击交付目录中的 **活动流程ERP-可点击原型.html**，即可在浏览器离线操作。也可打开 `prototype/index.html`，请保持其与 `app.js`、`styles.css` 同目录。

顶部为评审工具条，可切换 **PC 管理端／移动 H5**、演示身份和重置演示数据。切换终端会保留当前页面及业务数据。首次在窄屏打开默认 H5，可在手机浏览器打开同一文件；不同浏览器与设备间不共享本地状态。

所有示例由虚构活动和人员组成，邮箱使用示例域名。文件选择只保留名称；没有文件上传、外发通知、真实审批或付款。

## 1. 先看 PC 工作台与 H5 待办

默认身份：林晓／申请人。工作台显示待补充和待提交档案事项。点击活动名称进入详情；在移动 H5 下查看卡片、底部导航与单列详情。

切换“陈宁／部门领导”，工作台会切换到本人可审批事项。切换“许言／系统管理员”，只显示配置入口；管理员不获得业务审批权。

## 2. 完成三层审批与执行指派

1. 切换 **陈宁／部门领导**，进入“阅读教学与表达课例研讨”，点击“同意”。
2. 切换 **周岚／分管院领导**，打开同一活动并同意。
3. 切换 **赵明／营销中心领导**，打开同一活动并同意。此时状态为“待指派”。
4. 切换 **王舟／活动协调员**，指派苏禾为执行人，填写至少 5 字的安排。
5. 切换 **苏禾／执行人**查看安排。未来时间的活动会阻止提前开始。

要直接体验开始与汇报，可选择预置的 **“课堂观察与教学视导活动”**，其计划开始在演示数据生成时的两小时前。点击开始执行，随后填写实际时间、实到人数与至少 10 字总结。

## 3. 完成执行汇报与归档

1. 苏禾进入预置 **“秋季阅读示范课交流”**，填写并提交执行汇报。
2. 切换林晓，找到同一活动，点击“提交活动档案”，填写至少 10 字成果摘要与有效 HTTPS 成果链接。
3. 切换 **何青／归档审核人**，确认三个归档检查项并通过。
4. 工单变为“已归档”，申请和结果只读，档案列表可查。

也可从林晓的 **“小学语文教学成果交流”** 开始提交档案，从何青的 **“跨学科教研实践分享”** 直接体验归档审核。成果示例链接仅用于格式演示；正式产品需验证实际资料访问权限。

## 4. 体验退回、重提与版本留痕

1. 陈宁进入“阅读教学与表达课例研讨”，选择“退回补充”，写至少 5 字具体原因。
2. 林晓在待办中打开活动，查看退回原因并修改申请，保存或重新提交。
3. 重提生成申请 V2，从部门节点开始，保留 V1 的办理历史。
4. 详情“查看申请版本”可切换旧版快照；历史视图隐藏办理按钮，切回当前内容继续办理。

预置“新教师课例研磨专题活动”已处于待补充，可直接体验补充重提。审批中申请人可以撤回，填写修改后重新提交。

## 5. 发起一张新申请

林晓点击“发起活动”，按“基本信息 → 方案与人员 → 预算与提交”填写。任一步均可保存草稿；切换演示身份前会先保存当前草稿。返回时会提示放弃未保存修改。

重点查看：

- 线上需要会议链接，线下需要地点，混合两者都要。
- 费用总额由明细自动合计；0.00 元有效，负数、空金额和三位小数不可提交。
- 收费培训必填培训要求；“其他”分类需补充说明。
- 姓名、人数、联系方式和申请时间有局部校验。
- 开始时间在过去不可提交；距开始不足 3 天会要求说明。
- 原型预算单项金额上限为一亿元，用于保护演示数值精度。

## 6. 体验取消审批

1. 林晓或王舟打开“区域教研共同体专题培训”等已批准活动，申请取消并填写原因。
2. 活动进入“取消审批中”，执行、指派、汇报动作冻结；执行中取消还要填写费用处置说明。
3. 陈宁同意取消，工单进入已取消；拒绝则恢复申请取消前的状态。
4. 取消申请发起人可撤销取消请求并恢复原流程。

## 7. 体验规则分支与在途版本

1. 许言在 PC 管理端进入“流程设置”。
2. 勾选“预算达到阈值时追加院负责人审批”，输入 10000 元阈值，使用测试预算预览路径。
3. 保存草案与发布分开；发布 V2 后新提交生效。
4. 林晓发起／重提总预算 10000 元的申请，可见三层后追加刘文；9999.99 元仍为三层。
5. 发布前已提交的工单仍使用 V1 三层路径；刘文仅能查看和处理实际分配给自己的工单。

提醒时间参数可编辑和保存，但本地原型不运行消息调度。组织受理人映射固定为演示员工。

## 8. 本次交付校验

已完成：JavaScript 静态语法检查，必要的纯逻辑局部校验，原型入口及引用文件检查，PRD 与交互动作对照。局部校验包括金额边界、条件路径、状态与角色约束、重提版本及取消恢复等。

按项目要求未运行构建、项目服务、浏览器预览、端到端测试或 Git 操作。实际布局、手机键盘／安全区及全部点击路径由本次评审确认。

## 9. 优先讨论的决策

先确认 PRD 的 Q01—Q08：活动纳入范围、三层审批规则、指派与接收职责、归档职责、批准后修改、紧急／补录通道、财务边界、账号与通知来源。剩余参数可以在试点前确认。

建议记录：问题编号、页面或状态、最终决策、负责人、确认日期。原型通过顶部“重置演示”恢复全部样例，重置前会再次提示。
