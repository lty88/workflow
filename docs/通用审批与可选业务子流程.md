# 通用审批与可选业务子流程

## 已实现的两种方案

模板设置增加业务类型及“审批通过后”配置。通用OA申请绑定独立表单，全部生效必办节点完成后直接办结；活动申请可选择仅审批办结或接续标准活动执行与归档。方案带版本并随模板发布及申请提交冻结，编辑模板不修改在办实例。

标准活动子流程V1：最后实际审批人指派执行人 → 执行人持续汇报并手动完成 → 执行人提交成果 → 最后审批人归档审核 → 整单办结。无审批节点的活动仍采用原协调人及独立归档岗位。归档退回只重开成果提交和审核轮次，已完成执行记录保留。

新活动的业务步骤真实保存为节点与个人任务，复用同一套任务版本、事务、审计、通知。业务待办只通过对应业务动作完成，通用审批/任务完成接口不能跳过指派、执行完成或成果检查。一次执行任务可追加多篇汇报，不按每篇日志创建新节点。

## 使用

1. 运行数据库增量迁移：项目根目录执行 `pnpm db:migrate`。此版本只创建 requests、request_nodes、request_tasks、request_edges、request_files，登记第9版；不复制旧活动、不调整旧表外键。
2. 配置中心新建模板时选择“通用OA申请”或“活动申请”。模板设置内选择审批后的接续方案；通用申请可用现有字段设计器配置自己的必填、显隐、权限及附件字段。
3. 已发布模板业务类型保持固定；不同业务创建另一模板。独立表单随模板保存与启用版本；普通申请不要求活动时间、人数或预算。
4. 从“申请中心”点击“发起活动”下拉按钮，选择“通用审批”或“活动申请”。申请中心、活动/待办/归档列表、工作台快捷入口及桌面/移动导航共用该入口；活动申请继续选择活动类型与模板，通用审批直接选择模板。申请中心、活动工单及既有待办列表查询跨业务记录，可按业务类型筛选；活动档案、评价和业务统计继续使用原活动口径。
5. 普通申请详情展示申请资料、节点资料、办理记录，隐藏执行归档和活动评价。系统自动留存记录，不要求用户额外提交成果归档。

## 存储与兼容

使用固定的存储适配器，旧活动沿用 activities / workflow_nodes / workflow_tasks / workflow_edges / files，普通申请使用独立 requests 及关联表。引擎、权限、表单、动作、附件、通知代码共用，不创建OA占位活动。

通用主单保存整体 case_status、approval_result、current_stage，以及兼容运行接口的 status；审批通过即办结时整体 completed、结果 approved、阶段空。主单JSON保存表单和申请版本快照；节点及个人任务独立保存，根表不承载活动执行、汇报或档案内容。

新增迁移仅增表；启动前同时检查第9版登记及5张新表是否完整。新通知轮询和消息列表、附件阅读与下载、列表导出以及成员历史引用保护均覆盖两类申请。

当前申请版本作为流程实例边界，节点 generation 作为重办轮次。活动子流程通过 businessStage 标识真实步骤，只有正常业务命令触发同步；不批量生成旧活动的历史待办。旧活动尚无业务步骤时，详情按原状态及同一注册方案兼容展示，首次正常业务变更后保存真实步骤。

历史未声明接续方案的模板和活动继续使用原活动闭环V1。原有审批人、执行人、归档审核人和已完成历史保留。旧API路径继续兼容，新通用路径为 /api/requests；节点决策与转交继续复用 /api/tasks。

## 权限与原子性

复用现有申请/活动查看、创建、提交和审批权限码及角色数据范围，保留现有授权；服务端依据真实会话、当前待办、模板冻结规则再次校验。新增页面入口也检查权限。

审批通过、接续节点创建、主单推进、任务和审计落库、通知出站均在原单据事务内执行。接续同步按申请版本和步骤幂等，不会重复生成执行任务。审批任意退回限定审批段；业务阶段不通过审批接口回跳，归档退回只回到成果补充。

## 迁移边界与验证

本次交付包含迁移脚本，未执行数据库迁移。全量旧活动复制和旧外键重定向方案被自动审批拒绝后，改为仅新增表的增量方案，旧库结构与数据保持原样。

验证采用前后端静态检查和内存/模拟数据库局部校验，不构建、不启动项目、不运行浏览器或真实数据库端到端验证。


## 工单查询、终止与删除

活动工单与申请中心默认展示授权范围内两类申请的全部状态，终止（rejected）、取消、撤回、办结等不会自动隐藏。业务类型、状态、关键词、本人筛选可以组合，分页数量与导出沿用同一条件。我的待办仅展示当前可办理事项，活动档案仅展示已归档活动。

终止申请是审批节点被授权办理人作出的业务决定，结束剩余流转并保留可查询记录；删除是记录清理，写入逻辑删除标记后从日常入口隐藏并保留底层历史。普通发起人仅能删除本人草稿、待补充、已撤回、已终止或已取消记录。在办申请按阶段先撤回或申请取消，无需为了删除强行走审批终止；已有管理员删除权限仍允许按授权范围例外清理任意状态，需填写原因并留审计。


## 附件与节点资料权限

附件先要求所属申请可读。未提交分组仅上传人可见；节点文件未单独配置时继承提交时冻结的节点规则，显式共享或指定文件受众后按该文件规则判断。动态字段附件还必须同时满足真实引用表单的字段权限，单文件共享不能绕过字段限制。独立通用表单及不同ID表单的同名字段不再串用活动公共表单规则；历史附件保留原快照的表单归属与限制。

下载同时要求文件可读、角色具备对应数据范围的下载权限、文件有效下载范围允许。查看与下载独立，详情会明确区分角色未授权下载和不在文件下载范围；在线预览和直接下载接口均重新校验实时权限。

节点资料默认保留本次申请的退回、终止或失效节点，业务状态不再把有权阅读的本轮资料隐藏。历次申请节点使用历史开关展示，文件仍由服务端授权过滤。模板权限变更只影响后续提交，不回写在办申请；新文件默认权限只影响之后的上传，已有文件需逐个通过单文件权限修改。

### 新申请节点附件默认共享

新提交时，未配置附件查看规则的节点显式冻结为 shared（流程内共享），后续审批人及其他有权查看申请的人员可查阅已提交附件。模板明确设置的 restricted 规则继续冻结并执行。节点与单文件都提供“流程内共享”“仅本节点办理人”“指定人员或角色”；文件保留“按节点设置”，用于沿用实例冻结规则。未提交分组、动态字段权限、角色下载能力、文件独立下载范围继续校验。

已有申请不修改、不重新实例化，缺失节点权限时继续执行旧版私有默认值。历史附件的批量共享需另行明确确认范围；单文件授权入口可按需调整。

### 直接前置成果评分与默认范围展示

评分按流程依赖关系，不按页面上下排列。开启评分的审批节点评价本轮已完成的直接前置审批或任务成果；中间知会不作为成果，按其前置穿透查找。并行同级和间接祖先不进入评分对象；并行汇合按各直接前置分别评分。任务办理人只完成任务，暂不作为评分发起人。原评分总开关、节点选填/必填、多人会签、0～100整数及重办轮次隔离保持原规则；不回填已完成历史评分。

附件默认选项直接显示“流程内共享（节点默认）”“仅本节点办理人（节点默认）”或“指定人员或角色（节点默认）”，值来自服务端对本次申请实例的实际规则解析；上传折叠区外也显示默认范围。单文件同时显示实际查看范围，权限弹窗显示默认下载范围。此展示不改变已有申请授权，不需要用户重新配置模板；模板中的权限只在提交申请时冻结。旧申请缺失规则的私有默认值照常展示。
