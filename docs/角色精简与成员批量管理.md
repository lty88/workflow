# 角色精简与成员批量管理

2026-10-23 已完成代码和当前本机数据库更新：56 个角色合并为 9 个，121 个账号同步角色关联，30 个部门保持原结构。

## 通用角色

| 角色 | 用途 |
| --- | --- |
| 系统管理员 | 用户、组织、表单、菜单和权限维护 |
| 活动管理员 | 全公司活动管理、活动删除 |
| 活动发起人 | 创建、提交及维护本人活动 |
| 部门负责人 | 本部门及下级活动查看、审核 |
| 业务审核人 | 办理指派给本人的跨部门审核与任务 |
| 流程协调人 | 调整节点、协调流程、指派执行人 |
| 活动执行人 | 办理任务、活动执行与成果提交 |
| 归档管理员 | 成果审核、活动归档 |
| 公司领导 | 领导审核、公司活动查看、领导看板 |

角色定义业务能力，部门定义人员归属。财务、策划、设计、技术研发等部门共用这些角色，不再按部门复制岗位角色。一个人可以兼任多种职责；不需要让所有人拥有全部角色。

每个部门负责人已关联“部门负责人”和“业务审核人”，普通部门测试账号保留“活动发起人”和“活动执行人”。当前活动管理员暂无单独人员，可根据管理职责分配。系统管理员保留活动删除权限。

角色授权页面按管理、申请审核、协调执行归档、领导四组展示，显示各角色用途。敏感信息仍遵循字段、节点及附件的数据权限；本次将原有敏感规则中的角色受众固定为原有有效人员，避免合并扩大受众。受众发生组织调整时，可再编辑相应规则。

## 审批节点选人

- **申请人所在部门负责人**：沿用活动申请人的部门，不随节点名称改变。例如节点命名“财务部”，仍不会自动选择财务。
- **指定部门负责人**：明确选择“财务部”“技术研发部”“教学质量部”等部门，按该部门维护的负责人受理。无需创建部门专属角色。
- **角色**：选择“业务审核人”会匹配符合该受理规则的角色人员，适用于共享审核岗。明确的部门审批优先用“指定部门负责人”。

新增“指定部门负责人”的前后端类型、配置校验、受理计算、图节点说明和运行中加签已贯通。负责人缺失或无效时禁止选取或提交。

## 成员勾选与批量操作

组织架构人员区域支持单选、多选、全选当前筛选结果，最多 200 人。切换搜索、部门或重新读取后清空选择，避免误操作隐藏人员。当前账号及初始管理员不参与选择。

批量启用、批量停用、批量删除均先弹出确认，展示人数和账号。服务端在事务中先校验整批，任一成员不符合规则，整批不执行，并显示原因。

- 启用：保留密码、角色与部门；所属部门停用时仍需恢复部门才能登录。
- 停用：撤销该账号现有登录会话，保留待办与历史；部门负责人须先交接。
- 删除：复用单人删除的引用检查与物理清理；存在业务历史、模板或权限等引用时先处理关联。
- 自身账号、初始管理员受到保护；并发修改需刷新后重新操作。

接口：`POST /api/members/batch`，需要 `config:manage` 权限。

```json
{
  "action": "disable",
  "ids": ["member-id-1", "member-id-2"],
  "expectedRevision": 1
}
```

`action` 可为 `enable`、`disable`、`delete`。`expectedRevision` 使用最近读取的实际主数据修订号，成功返回更新后的实时主数据。
