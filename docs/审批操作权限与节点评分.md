# 审批操作权限与节点评分

## 模板配置与使用

模板设置增加“节点办理质量评分”总开关，默认关闭。具体审批节点在“办理规则”配置：

- 允许退回修改，默认开启。
- 退回范围：默认上一步，或指定上游审批/任务节点；支持选中全部当前上游。
- 允许退回发起人，默认开启。首节点无上一步，可退给发起人。
- 允许终止整个申请，默认关闭。会签中任何当前办理人均按此节点配置执行。
- 上游评分：不评分、选填、通过审批时必填。模板总开关开启后生效。对象为实际生效的直接前置审批节点，首节点、任务、知会无评分。

保存模板设置/修改后，启用新版本，后续新提交的活动冻结这版规则。已有活动的节点规则保持原样。

## 退回语义

运行目标必须是本次申请中已完成、实际流经的上游审批或任务节点。上一步模式只允许有效直接前置；指定上游模式还需位于模板保存的明确白名单。系统起止、未来、自身、无关分支、未生效节点、旧申请节点不可选。接口在事务锁内复核目标及其轮次。

退回节点时，目标及其依赖后续开启新办理轮次，旧待办取消，旧通过意见保留。独立并行分支的结果和待办保持有效，汇合节点重新等待受影响前置。保持同一个申请版本，重新依序办理，不自动跳回原退回点。

退回发起人用于修改活动申请内容；沿用 needs_info，取消本轮剩余待办，成功重新提交后申请版本递增并重新审批。省略目标只保留旧客户端退给发起人的语义，仍需本节点允许。

运行中转交过的节点重办时保留明确转交人资格；当前账号、角色、活动范围仍实时核验。失去资格时由现有转交能力处理，不静默改派。

已发送的知会不撤回。其依赖成果重新办理后，受影响的知会形成新轮次并发送新的通知，历史投递仍保留。

## 评分语义

B办理时评价A：0～100整数，零分有效。每个会签人独立保存，汇合处分别评价各直接前置审批成果。通过时按必填配置校验；退回、终止时原因必填而评分选填。评分不自动决定审批结论。

评分关联来源个人任务和被评节点轮次。来源节点或被评成果重办后，旧评分标为历史评分，不算作当前有效评价。分数、评分人和办理轮次在办理进度中展示。评分及审批意见面向有权查看活动的人员。

## 审批意见与附件

移除新办理的节点内部说明输入、提示和进度展示；只保留公开审批意见。旧客户端提交非空 comment 时返回明确校验错误，禁止继续写入私密说明。历史私密内容保留数据库原记录和原有审计授权，不自动转为公开内容。

节点数据权限改为“节点附件查看范围”“节点附件下载范围”。节点及单文件既有授权逻辑继续生效，单文件共享只影响该文件。

## 终止与界面

审批抽屉底部固定：红色描边“终止申请”、橙色描边“退回修改”、蓝色“通过审批”。仅显示服务端下发允许的操作。任务节点只提供完成任务。

退回弹窗展示目标、重办范围、原因。终止弹窗展示活动、将取消的待办数量、不可继续流转的后果及必填原因。终止后状态沿用 rejected 存储，界面统一显示“申请已终止”，源节点红色，其他取消节点灰色并说明原因。退回源点及待重办节点橙色，普通在办节点蓝色。

## 接口与持久化

沿用 POST /api/tasks/:taskId/decisions，扩展 returnTargetId、expectedTargetGeneration、ratings。退给发起人时 returnTargetId=applicant；退给节点时为运行节点ID。ratings每项包含 nodeId、generation、score。publicComment为唯一新办理意见，comment仅保留空值兼容。

详情增加 decisionCapabilities，按当前用户与当前任务下发可退回目标、服务端计算的影响范围、终止能力及评分对象。客户端不推断授权，服务端在实例事务锁内再次校验，保留任务版本与幂等控制。

复用现有独立 workflow_nodes / workflow_tasks 表的 data JSON：节点冻结 approvalPolicy，重办保存 generation/rework；每个人的评分、目标和受影响范围保存在对应任务的 ratings/returnTargetId/returnAffectedNodeIds。审批公开意见同时写入审计 publicNote，与旧受限 note 分开。所有写入沿用现有单活动事务，不需要改表或批量重写历史。

旧运行实例未保存 approvalPolicy 时，沿用原“退给发起人、允许拒绝”策略。旧模板进入编辑草稿时补齐保守默认规则；原发布历史及运行实例不改写。新加签审批也默认关闭终止与评分。
