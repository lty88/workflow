# 配置中心评审指南

版本：V0.3 · 日期：2026-10-21

## 打开

双击“活动流程ERP-配置中心.html”，或刷新首版原型后点击顶部“配置中心”。分文件入口为 `prototype/config.html`。

配置工作账号固定为许言；“联动体验”的员工切换用于验证业务侧身份，与配置工作账号分开。数据优先保存在当前浏览器，本配置中心与此前两个演示分别保存。

## 1. 动态表单

1. 进入“动态表单”，新增一个“培训目标”字段，字段键 `training_goal`，类型选多行文字并设为必填。
2. 右侧草案预览立即出现该字段，点击校验可检查必填。
3. 将举办方式切换为“线上”，活动地点隐藏且不参与必填；切回线下恢复。
4. 试着删除“预算总额”，系统会指出院负责人条件正在引用该字段。
5. 修改草案不会改变已发布体验；发布后再选择“已发布”体验新表单。

字段可以编辑、排序、删除；活动名称为系统保留的必填文字。已有字段键保持稳定，被条件引用的字段不能直接删除或更换类型。

## 2. 动态流程节点

1. 进入“流程节点”，右侧默认按林晓／教研一部解析受理人。
2. 将测试预算从 8000 改为 10000，院负责人节点出现。
3. 新增一个审批节点，选择角色或指定员工，按节点之前／之后／并行插入。
4. 要使用“办理任务”，负责人需要“办理任务”和“查看活动”权限；知会为非阻塞。
5. 在组织中调整教研一部负责人，返回此页观察部门初审受理人变化。

部门初审标记为必要审核，保持审批类型且不能配置跳过条件。原来的专门“动态流程图”仍可体验完整执行、子流程和归档；本配置中心的运行区聚焦“动态表单提交 → 审核任务生成与办理”。

## 3. 公司组织架构

选择公司／部门，查看直属成员和负责人。可新增部门、员工，编辑成员主部门与多角色，启停员工。

新部门先添加成员，再指定本部门有效成员为负责人。若负责人调离或被停用，发布校验会要求同步修复负责人配置；设为暂未配置可以发布，新申请提交时会明确提示缺少受理人。组织主数据来自权威账号系统的正式方案见设计文档。

## 4. 审核权限与数据范围

“角色权限”分别配置操作、页面和数据范围。建议依次体验：

- 林晓／申请人：看到本人申请、可以发起，不获得审核权。
- 陈宁／部门审核人：看到教研一部的数据；不会看到教研二部活动。
- 乔安／教研二部申请人：只看到本人活动。
- 周岚／教研审核人：提交前没有相关任务，实例分配后可查看该活动；仅在前置完成后审核。
- 许言／配置管理员：只看到配置概览，没有业务读取或审核能力。

撤销审核角色的“审核活动”权限并发布，再打开原有任务，审核按钮消失。直接办理逻辑也会重新检查资格。配置管理员账号本演示固定为许言，需要保留其管理权限；正式系统的管理交接需切换真实账号。

## 5. 动态菜单页面

1. 新增“我的活动看板”，模板选活动列表，授权申请人。
2. 在联动体验中选择草案，林晓和乔安都会看到新入口，各自仍只看到本人数据。
3. 停用页面或父分组后入口消失。
4. 点击运行区“验证直接访问页面”，选择一个当前员工未授权的页面，显示访问拒绝。
5. 发布新配置后，切换至已发布来源再验证。

新增页面复用已注册模板，不执行任意脚本，不改变数据权限。模板包括工作台、活动列表、申请表单、任务列表、档案列表和配置概览。

## 6. 完成一次联动提交与审核

1. 保持初始配置，进入联动体验，选择“已发布 C1”和林晓，点击“发起活动”。
2. 预算 8000 元会解析三层中的部门节点与教研／营销并行节点；10000 元再增加院负责人。填写后提交。
3. 切换陈宁，进入“我的待办”，打开新活动并模拟同意。
4. 周岚与赵明此时均有可办理任务，可任意顺序完成；10000 元申请还需刘文完成复核。
5. 必要节点全部完成后显示“审核完成，待安排执行”，不直接把活动标成已完成。
6. 修改表单标题或新增字段、修改流程，发布 C2，再提交新活动。旧实例仍展示旧字段与旧流程快照，新实例使用 C2。

如果选择“草案”体验，提交的实例会标为“草案体验”，不代表配置已发布。运行表单校验也会阻止结构无效的草案生成实例。

## 校验范围

新增三个脚本均完成静态语法检查；必要局部检查覆盖配置引用、字段显隐、金额阈值、受理规则、自审、数据范围、菜单／页面直接访问、并行任务、权限撤销及新旧版本快照，另包含各模块与多身份的模板生成。

按项目约定未构建、未启动服务、未打开浏览器预览、未做端到端验证，未执行 Git 操作。页面布局和真实点击体验留给交互评审确认；服务端身份、文件权限、事务与并发由正式实现负责。
