# 多流程模板代码实施说明

日期：2026-10-22。范围：将已评审原型接入现有 Vue 3、Naive UI、G6、Fastify 和 MySQL。

## 使用入口

- 管理员：配置中心 → 流程模板。原“动态流程”页已改为独立模板库。
- 申请人：发起活动 → 活动类型 → 审批流程模板 → 填写申请 → 计算实际路线 → 提交。
- 活动详情：显示模板名与发布版本；历史申请展示当次模板来源；实例新增节点标记“本场新增”。

## 首次升级

当前数据库需要显式升级；本轮没有连接数据库或自动执行迁移。先停止已有开发服务，然后在项目根目录运行：

```sh
nvm use
pnpm db:migrate
pnpm dev
```

以上是用户部署步骤，本轮未运行启动命令。新数据库继续使用 `pnpm db:init`，其中已包含模板迁移。

迁移会创建活动类型、模板、不可变发布版本、类型关联和目录锁表，在活动表增加3个可空模板索引字段；保留原活动JSON、审批节点、个人待办、审计、账号和密码。使用迁移版本2防止重复导入，重复执行不会覆盖模板编辑结果。

初次导入标准教研、线上公益研讨、收费培训、内部分享4套模板；标准模板复制数据库当时已发布的原流程。适用类型预置教研交流、阅读项目、线上研讨、收费培训、内部分享；一个模板可关联多个类型，每个类型可有多套模板。

初始授权部门取现有有效申请人所在部门，现有示例组织为教研一部、二部。如果公司组织已改造导致某模板受理角色或负责人不合格，该模板只导入草稿，不发布；管理员在模板库修复并发布后再申请。管理员可调整授权范围；空部门表示全部部门，非空包含下级；空角色表示所有具有申请权限的角色。

## 已实现

1. 模板库：名称/编码搜索、类型/部门/启停筛选、新建、复制、启停、删除未发布且无业务引用草稿、发布历史。
2. PC设计器：节点库拖入前/后/并行接入区，右侧属性与前置编辑，G6自由连线与删线，节点坐标保存，自动排列，40步撤销重做，条件与真实受理人演算。
3. 草稿与发布独立：乐观锁防止多人覆盖；模板发布与全局组织/菜单配置发布分开。发布捕获当前已发布动态表单。
4. 模板授权：活动类型、部门及下级、角色与活动操作权限共同限制；管理员身份不附带活动发起或审批权限。
5. 活动申请：保存类型/模板/预览版本，采用对应发布表单；输入或选择变化后清除旧预览；模板版本冲突会刷新选择并要求重新确认。
6. 服务端实例化：在活动事务中共享锁定模板发布指针；版本、启停、范围、表单和实际办理资格重新校验；按原DAG引擎产生独立节点和任务。
7. 快照和历史：每轮申请记录模板ID、版本、名称、活动类型与定义摘要；保留旧申请记录；模板更新/停用不改在途实例，实例加签/转交不回写模板。
8. 退回/撤回重提：明确使用该模板最新发布版本，重新预览；原模板不可用时选择其他可用模板。旧工单无模板信息的历史显示为“历史流程快照”。
9. PC/H5：两端均可选模板、预览和办理；手机端模板设计只读，可演算，复杂编排和发布使用PC。

模板设计共用现有活动申请表，审批后仍走公共的指派、执行、汇报和归档阶段。类型当前采用预置目录；独立类型管理页面、每模板不同表单、或签、子流程、脚本节点不在本轮范围。

## 关键规则

- 每套模板保留始终进入的部门负责人初审。多人审批沿用全员通过，知会不阻断，多个必办前置全部完成后激活后继。
- 标准模板预算≥10000元复核；收费培训始终院负责人复核；线上公益为部门＋教研；内部分享为部门＋资料任务。这些初始模板都可通过发布新版本调整。
- 发布前检查环路、引用、条件值、必要审核、授权范围、所有条件分支的受理资格、自审和数据范围，防止条件尚未命中而掩盖配置问题。
- 默认推荐按活动类型与部门范围检查冲突，防止上级部门和下级部门的默认范围重叠。
- 移动坐标仅改变布局，连线或前置变更才改变流转。自由连线不能连接公共展示阶段。
- 停用允许管理员明确操作；界面提醒该类型可能暂时没有可选模板。在途活动继续，新的提交与重提重新检查可用性。
- 公共表单变更先在动态表单中发布，再发布相关模板版本；模板旧版本仍保留其原表单。

## 新增接口

均使用现有真实会话、CSRF和统一错误格式；管理员写入使用幂等键与草稿版本。

| 方法 | 地址 | 作用 |
| --- | --- | --- |
| GET | /api/activity-types | 当前申请人可用类型 |
| GET | /api/workflow-templates | 授权模板摘要与冻结表单，可按activityTypeId过滤 |
| GET | /api/workflow-templates/:id/versions/:version | 当前可用版本，管理员可看历史 |
| POST | /api/workflow-templates/:id/preview | 实际申请路线预览 |
| GET | /api/admin/workflow-templates | 模板草稿目录、类型与组织上下文 |
| POST | /api/admin/workflow-templates | 新建或复制草稿 |
| PUT | /api/admin/workflow-templates/:id/draft | 保存草稿 |
| POST | /api/admin/workflow-templates/:id/validate | 校验未发布定义 |
| POST | /api/admin/workflow-templates/:id/preview | 管理员演算草稿 |
| POST | /api/admin/workflow-templates/:id/publish | 发布独立版本 |
| POST | /api/admin/workflow-templates/:id/active | 启停 |
| DELETE | /api/admin/workflow-templates/:id | 删除无引用未发布草稿 |
| GET | /api/admin/workflow-templates/:id/versions | 不可变发布历史 |

活动创建/编辑增加 `activityTypeId`、`templateId`、`expectedTemplateVersion`；提交增加 `expectedTemplateVersion`。旧草稿可明确迁移选择默认模板，未提交阶段不创建任务。原 `/api/workflow/preview` 保留默认标准模板兼容入口。

## 并发与一致性

模板写入先持有公司配置共享锁，再用目录锁串行化默认冲突与模板管理；保存/发布校验draftRevision。活动提交持有公司配置共享锁、活动排他锁、模板发布指针共享锁，模板发布持有模板排他锁，避免版本悄然切换。

事务保存申请快照、实例节点、个人任务、审计和通知发件箱。模板管理也使用现有幂等记录表，网络重试沿用请求标识。已发布版本仅插入，不更新历史记录。
