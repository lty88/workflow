# 活动评价与领导看板

## 业务范围

本期提供活动结束后的免登录匿名评价，以及按领导数据范围展示的活动运营看板。复用现有活动工单、执行汇报、组织、角色和动态菜单；不引入登录注册、签到、奖品、报销或通用报表设计器。

“活动完成”按执行汇报已提交计算：状态为待提交档案、待归档审核或已归档，且实际结束时间不晚于当前时间。归档资料补充不影响收集评价；取消、取消审批、拒绝和未完成活动不接受评价。

## 角色与权限

| 角色                   | 能力与数据范围                                                                                       |
| ---------------------- | ---------------------------------------------------------------------------------------------------- |
| 活动参与者             | 使用链接或二维码进入独立H5，无需账号；填写四维评分及匿名建议；只看活动名称、实际结束时间和问卷有效期 |
| 组织、执行、档案岗位   | 获得评价查看与管理能力，仍受该角色原有活动范围限制；可开关、换码、分享及查看分页反馈                 |
| 部门负责人             | 部门或部门树范围的活动汇总；原有敏感数据权限独立保留                                                 |
| 公司负责人、配置管理员 | 默认获“公司领导看板”角色，只增加全公司汇总看板，不因此获得活动审批原文或财务明细                     |
| 自定义领导             | 在角色权限中分配“查看领导数据看板”及对应数据范围、领导看板菜单                                       |

新增权限：`evaluation:read`、`evaluation:manage`、`dashboard:read`。评价权限和活动范围必须来自同一角色；看板按自身权限所在角色计算范围，接口在服务端强制校验。

## 完整使用流程

1. 执行人完成活动并提交执行汇报。
2. 组织者打开活动详情的“活动评价”卡片，选择7天、30天或90天，点击“开启活动评价”。
3. 生成该活动专属链接和二维码；支持复制链接、下载二维码及预览填写页。二维码在本地生成。
4. 参与者手机扫码进入独立H5，分别对整体满意度、内容质量、组织服务、实际收获打1至5星，可填写最多1000字建议。
5. 提交成功显示感谢页；同一浏览器每场活动只收集一次，重复网络请求返回成功且不重复计数。
6. 组织者查看评价数量、整体均分、满意率、低分数、维度得分、星级分布和匿名反馈；反馈每页10条。
7. 需要终止填写时“停止收集”；泄漏或误发时“更换链接”，旧二维码立即失效，已有评价保留。重新开启沿用原码并重设有效期。
8. 公司或部门领导从动态菜单进入“领导看板”，按日期、部门及活动类型筛选数据。

## 交互设计

- PC活动详情：独立评价卡片，开关状态、有效期及分享动作集中展示；分享弹窗提供240像素二维码、复制、下载和预览；低分反馈加关注标签。
- 公开H5：单列大字号布局、四组触屏星级评分、可选建议、提交和感谢状态；填写错误不丢数据；不展示内部导航。
- 领导看板：顶部筛选区、六项指标、月度双柱趋势、流程状态分布、部门数量与质量表、活动类型分布、低分活动关注列表；移动端自动改为单列图表与双列指标。
- 全部新增页面字体至少12px。普通登录及文件路由保持原有机制；公开填写采用独立 `feedback.html` 入口。

## 数据口径

| 指标       | 口径                                                              |
| ---------- | ----------------------------------------------------------------- |
| 时间范围   | 按活动计划开始日期，起止日期均包含；默认近90天，单次最多366天     |
| 活动总量   | 授权范围和筛选内已提交过的活动，不含草稿；包含取消与拒绝          |
| 执行完成   | 待提交档案、待归档审核、已归档                                    |
| 推进中     | 非草稿、完成、取消、拒绝的其他状态                                |
| 完成率     | 执行完成数 / 活动总量                                             |
| 实际参与   | 已完成活动执行汇报实到人数之和，单位人次                          |
| 整体均分   | 整体评分总和 / 评价份数，按份数加权                               |
| 满意率     | 整体4至5星份数 / 总评价份数                                       |
| 低分反馈   | 整体1至2星                                                        |
| 需关注活动 | 整体均分低于3.5，按均分升序、评价数降序，最多10场，始终显示样本量 |
| 无样本     | 数量为0，均分和比例显示“—”                                        |

评价随所评价活动进入相应活动日期统计期。看板不返回费用、预算、联系人、审批意见或节点资料，所有图表使用相同范围过滤。

## 数据模型与接口

- `activity_surveys`：活动ID、随机64位令牌、开关、到期时间、乐观锁版本、创建人和创建时间。每场活动一个当前入口。
- `activity_evaluations`：评价ID、活动ID、匿名浏览器摘要、四项整数评分、建议、提交时间。活动ID和浏览器摘要唯一，四项评分具有数据库范围约束。
- `GET /api/activities/:id/evaluations?page=1`：内部评价统计及分页反馈。
- `POST /api/activities/:id/evaluation-survey`：开启、关闭、换码，提交当前问卷版本。
- `GET /api/public/evaluations/:token`：最少公开信息及匿名Cookie；精确豁免账号认证。
- `POST /api/public/evaluations/:token`：校验评分、链接状态、结束时间、来源和匿名Cookie后提交。
- `GET /api/leadership/dashboard`：登录后按看板权限范围聚合。

公开提交不收集姓名、手机号或原始IP。浏览器令牌由HttpOnly Cookie保存，数据库存按活动计算的摘要。换浏览器或清除Cookie后可再次提交；本期防重复口径为浏览器，不做实名唯一。公开提交按浏览器每分钟10次限流，公开读取按IP每分钟300次，兼容会场共享网络。分享令牌置于H5 URL片段，公开接口关闭令牌请求日志。

## 异常与验收

1. 未完成活动开启评价，返回业务提示；隐藏或绕过按钮直接请求同样拒绝。
2. 已关闭、到期、取消的活动或旧链接，公开页展示无法填写；并发提交时在活动与链接锁下再次校验。
3. 同一浏览器重复提交只保留一份；换码和重新开启不清空去重记录或既有评价。
4. 评分缺项、0分、6分、小数、超长建议、额外个人信息字段均拒绝。
5. 非登录用户能提交公开评价，但无法访问内部评价列表、配置或领导看板。
6. 申请人不能读取其他申请人的评价；多角色权限不能拼接成更大的评价管理范围。
7. 部门看板不返回其他部门活动；任意修改查询部门参数仍受原有范围约束。
8. 看板总数和图表不受列表分页影响，单次读取使用同一事务快照；平均分按份数加权。
9. 接口失败时显示错误和重试入口；匿名填写保留已填内容；看板丢弃晚到的旧查询结果。
10. 迁移增加表、菜单与授权，在事务中保留发布配置及独立草案；原有密码、活动历史和敏感内容权限保留，重复迁移不重复授权。

## 环境与上线

运行 `pnpm db:migrate` 安装评价表和默认看板授权，新库初始化也会安装。更新服务后刷新登录身份即可取得菜单。前端构建包含主系统与独立评价页两个入口，无需原生App。

可在 `.env` 设置 `PUBLIC_APP_URL=https://公司前端域名` 指定二维码与分享链接域名；不设置时使用当前浏览器地址。手机填写需能访问此域名及同源 `/api`；本机localhost链接只适合本机预览。前端代理需同时提供主系统和 `feedback.html`，生产环境使用HTTPS。

## 待确认业务问题

- 是否需要限定仅受邀参与者填写？当前按持有链接即可填写，后续可增加一次性邀请码。
- 评价是否需要自动开启？当前默认由组织者在执行完成后开启，避免误分享。
- 是否需要按活动类型配置不同评分维度？当前统一四维，便于横向比较。
- 是否需要增加评价内容保留期限、敏感词审核和处理闭环？当前授权岗位可查看全部原始反馈，低分汇总在看板关注列表展示。
- 公司领导与部门领导的正式名单及是否需要额外的财务经营指标，后续可按角色授权扩展。
