# 动态表单附件上传字段

## 使用方法

1. 打开「动态表单」→「新增字段」。
2. 输入字段名称和稳定字段键，例如“活动方案附件” / `proposal_files`。
3. 控件类型选择「附件上传」，设置必填、最多上传数量、单个文件大小及允许格式，保存。
4. 根据资料敏感程度设置该字段的查看和填写权限，可使用条件显隐。
5. 流程模板的已发布版本保留原表单快照。要让新增活动使用这个字段，需要将相应流程模板发布新版本；既有活动和历史快照继续保留原版本。
6. 发起活动后在「内容与预算」步骤上传。首次上传会自动保存当前填写内容并建立草稿，无须先手动点击保存。

## 交互和校验

- 每个附件字段独立管理，默认每字段最多 10 个、单个 20MB。可配置 1 至 10 个，单个 1 至 20MB。
- 格式支持 PDF、JPG、JPEG、PNG、DOCX、XLSX，可按字段限制为其中一部分。
- 前端检查大小和扩展名；服务端同时检查文件签名、大小、数量、所属活动、字段、当前可见性和填写资格。
- 一次选择并上传一个文件，上传时锁定当前申请操作，结束后刷新主单版本。
- 必填附件需要至少一个文件，点击下一步即校验。条件隐藏时不阻止提交。
- 附件不支持默认值，也不能作为流程分支或其他字段显隐条件的来源；附件字段自身支持条件显示。
- 附件可移除引用，随表单保存生效；历史申请快照引用的文件保留。
- 复制为新活动时清空附件引用，需要重新上传，禁止跨活动借用文件ID。
- 配置试填预览不实际上传文件。

## 权限与展示

附件文件名、预览和下载均继承字段读取权限，同时叠加既有附件独立授权。下载还需要 `file:download`。直接请求文件地址也会再次校验权限。

申请详情把附件字段独立展示为「申请表附件」，支持当前与历史申请快照。PDF、JPG、PNG支持在线预览，其他格式按下载授权提供下载。原有“申请附件”和执行、归档、节点附件继续使用原入口，字段附件不混入这些列表。

## 接口与存储

配置字段类型为 `attachment`，可选规则如下：

```json
{
  "upload": {
    "maxCount": 5,
    "maxSizeMB": 10,
    "extensions": ["pdf", "docx"]
  }
}
```

沿用 `POST /api/activities/:id/files?stage=application` 上传接口；multipart 的 `access` 增加 `fieldKey`，值为稳定字段键。上传成功后，文件元数据及 `activity.payload[fieldKey]` 的文件ID引用在同一事务中保存。表单字段值沿用字符串协议，内部为 JSON ID 数组。

数据库第七版迁移增加 `files.field_key VARCHAR(40) NULL` 和 `(activity_id,stage,field_key)` 索引。历史附件此列为空。本机数据库已执行该增量迁移；其他环境执行 `pnpm db:migrate` 后重启服务。无需重新初始化或清空数据。

## 验证

前后端类型检查及附件上传、必填、分步校验、权限、历史快照和数据库就绪检查的局部用例。不进行项目构建、启动或浏览器端到端验证。
