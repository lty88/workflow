## 现有系统操作

1. 使用配置管理员打开“配置中心 → 组织架构”，点击顶部“补齐常用部门”。
2. 预览新增部门和角色数量。默认只补部门与岗位角色；需要测试账号时勾选“同时补齐示例负责人和成员”，弹窗会列出实际新增账号。
3. 点击“应用到草案”，检查部门树、负责人、成员及角色。
4. 点击“保存草案”，再“发布配置”。示例成员发布后创建登录账号，默认密码123456，可以在成员列表设置密码。
5. 打开流程模板设计器，按实际活动选择财务、策划、设计、印刷等岗位角色作为受理人，配置节点数据权限并发布对应模板。

负责人具有本部门初审和专岗审核资格；示例专员默认用于任务及执行协作。需要允许某位成员发起活动时，可单独授予申请人角色，并检查目标模板是否覆盖其部门。现有教研流程及其适用范围继续使用已有配置。

领导全量敏感查看、跨节点下载及配置管理继续按独立权限授予。新增示例账号按岗位配置权限。

## 补齐规则

- 已有同名或常用别名部门沿用原名称、层级和负责人，例如“财务中心”“市场部”“印刷部”。
- 已停用部门或上级保留停用状态，补齐预览会列出跳过的部门。
- 现有人员、账号和角色授权保持原配置。勾选示例人员时，仅为缺少负责人的部门建立示例负责人，仅在没有其他在职成员时补充示例专员。
- 标识、登录账号存在冲突时追加后缀，实际新增账号以预览及成员列表为准。
- 自定义角色与预置职责不兼容时新建独立角色，不把现有高权限角色自动分配给示例成员。
- 重复补齐只补缺项。草案保存、发布及新账号物化复用现有接口，无需数据库结构迁移。

## 直接批量导入数据库

在项目根目录执行 `pnpm db:seed-organization`，将常用部门及岗位角色一次性写入当前 `.env` 指向的数据库，刷新组织架构页即可查看，无需逐个新增或手动发布。

此命令只补齐部门和岗位角色，保留现有人员、密码与授权。发布配置和未发布草案分别补齐，保留各自已有改动；写入时更新版本、发布记录及操作审计，事务失败自动回滚。重复执行不会重复新增。示例人员仍可使用页面中的批量补齐选项添加。
