# 活动详情页面设计

## 阅读结构

- 顶部概况：活动名称、编号、状态；发起人单独展示，优先使用创建时留存的姓名，其次使用详情接口授权的参与人姓名；发起时间、流程模板、更新时间及当前进展常驻概况区。
- 申请资料：动态表单、方案、预算、申请表附件和补充附件；保留申请历史版本切换。
- 节点资料：各审批或任务节点的内部资料，沿用服务端数据权限和附件授权。
- 执行与归档：执行安排、实际汇报、成果附件及历次归档记录。
- 活动评价：保留现有开启评价、二维码与链接管理，以及反馈统计。
- 办理记录：完整操作记录，与右侧进度分开阅读。
- 右侧进度：保留本轮节点、个人意见、退回标识及完整流程图；窄屏时排在内容区下方。

## 底部办理栏

与设置中心采用一致的底部吸附方式，滚动长资料时仍可办理。活动详情页本身不再把主要业务按钮埋在申请内容末尾。

| 操作 | 视觉语义 |
| --- | --- |
| 提交申请、指派、开始执行、提交汇报、提交档案、办理审批 | 蓝色主按钮 |
| 完成节点任务、审核归档 | 绿色 |
| 撤回、申请取消、撤销取消、退回档案 | 橙色浅底 |
| 批准取消、删除活动 | 红色浅底，保留确认步骤 |
| 编辑、复制、调整流程、转交 | 中性实体按钮 |

个人并行待办可直接在办理栏选择节点，不必逐个寻找右侧“办理”。流程负责人也可在办理栏选择待转交的节点和人员，再打开原有转交抽屉。节点中的快捷入口继续保留，和底栏共用同一套任务资格判断。

附件上传、文件预览、评价链接管理等依赖具体资料上下文的操作保留在对应分区。所有按钮继续使用原有接口；底栏展示的是当前身份有权执行的操作。

## 权限与历史

- 服务端动作列表决定活动操作，个人办理进一步检查登录身份、任务归属、轮次、节点状态和操作权限。
- 自审、知会节点、受理异常、已处理任务不显示为个人可办待办。
- 查看历史申请时，顶部给出提示、底栏提供“返回当前申请”；提交、删除、转交和资料上传均保持只读。
- 删除按钮默认仍保持列表中的轻量样式，仅在详情底栏使用醒目的红色实体样式。

## 实现范围

本次调整仅涉及前端详情布局、入口及共享资格判断；复用现有活动、待办、附件和评价接口，无数据库迁移。按项目规则只进行静态检查与必要的局部权限回归校验，不启动项目或浏览器。
