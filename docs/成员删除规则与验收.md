# 成员删除规则与验收

入口：设置中心 → 组织架构 → 成员列表 → 删除。管理员确认后直接请求接口，成功后刷新成员列表、图表与主数据修订号，无需再次保存。

接口：DELETE /api/members/:id，body为 {expectedRevision:number}，返回最新ConfigState。权限沿用config:manage，页面、操作处理函数及事务内均检查。沿用会话、来源和CSRF校验。

- 允许物理删除未被业务引用的成员，直接移除members记录。
- 当前登录账号、初始admin禁止删除，始终保留有效管理员。
- 部门负责人需先完成负责人交接；包括停用部门中的负责人关联。
- 活动申请、执行、审批任务、节点、附件、模板及其历史版本、表单授权和操作审计存在引用时拒绝，提示处理关联或停用。
- 仅作为备份保存的旧整包配置不会阻止删除，也不会恢复被删除人员。
- 清理该成员会话、通知、通知待发记录及个人幂等记录；不删除活动、审批记录和附件。
- 清理、主数据版本更新和删除审计在同一事务内；审计保留成员ID、姓名和账号，不保存密码。
- 有本地未保存修改时先提示保存或重新读取；其他窗口携带旧修订号保存时返回409，防止把已删除人员重新写回。
- 接口返回409 MEMBER_IN_USE时展示具体引用原因；无权限403、账号保护422、成员不存在404。

验证：前后端类型检查通过，6项局部校验覆盖物理删除、负责人关联、活动引用、权限与账号保护、修订冲突、缺失成员、审计失败回滚及请求格式。未连接真实数据库删除成员，未启动服务或浏览器预览。本次无需数据库迁移。
