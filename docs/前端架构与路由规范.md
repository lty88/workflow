# 前端架构与路由规范

本次整理范围：路由入口、业务视图、动态菜单导航、活动详情拆分、接口归属与结构检查。工作目录为 `apps/web`。

## 1. 目录职责

```text
src/
├── pages/                    文件路由入口：读取路由参数、挂载业务视图
│   ├── index.vue             默认工作空间入口
│   ├── login.vue             登录入口
│   ├── account.vue           账号安全入口
│   ├── activities/
│   │   ├── new.vue           新建活动入口
│   │   └── [id].vue          活动详情入口
│   ├── workspace/
│   │   └── [pageKey].vue     服务端授权的动态工作区入口
│   ├── settings/             配置中心及各管理模块入口
│   └── [...path].vue         未知地址的 404 入口
├── views/                    按业务模块组织的页面实现与页面状态编排
│   ├── activities/           活动详情容器、详情状态 hook、页面类型
│   ├── workspace/            默认入口、授权页面读取、内置视图白名单
│   ├── settings/             配置概览
│   ├── auth/                 登录
│   ├── account/              账号安全
│   └── error/                404 展示
├── components/               现有业务组件与 UI 交互，按业务模块归属
│   └── activity/detail/      申请资料、执行归档、办理记录、只读展示计算
├── navigation/               跳转地址、菜单匹配、授权回退、配置页签目录
├── api/                      按业务拆分的接口函数，共用 http.ts
├── stores/                   会话与配置草案等跨页面状态
├── composables/              跨模块复用能力
└── typings/api/              接口类型；业务模型复用 @workflow/domain
```

依赖顺序：`pages → views / components → api / stores / composables / navigation`。页面入口可以直接挂载已有业务组件，简单入口不额外增加包装视图。组件不能反向导入 `pages` 或 `views`；接口层不能依赖页面、组件、导航或状态层。复杂模块类型放模块 `types.ts`，接口类型放 `typings/api/*.d.ts`。

## 2. 路由层级与动态菜单

| 访问地址                 | 页面职责                   | 权限与范围                             |
| ------------------------ | -------------------------- | -------------------------------------- |
| `/`                      | 按授权菜单进入默认页面     | 使用登录身份返回的菜单；无菜单显示空态 |
| `/login`                 | 登录                       | 保留现有会话恢复与登录回跳规则         |
| `/account`               | 本人账号安全               | 服务端校验当前会话与原密码             |
| `/activities/new`        | 发起活动或复制申请         | 沿用现有创建权限与模板授权检查         |
| `/activities/:id`        | 活动详情、编辑、办理及归档 | 服务端返回裁剪后的资料、任务与操作能力 |
| `/workspace/:pageKey`    | 动态菜单页面               | 先请求页面授权，再选择本地白名单视图   |
| `/settings`              | 配置概览                   | 配置管理权限                           |
| `/settings/forms`        | 动态表单                   | 配置管理权限                           |
| `/settings/workflow`     | 流程模板                   | 配置管理权限及模板操作校验             |
| `/settings/organization` | 组织架构                   | 配置管理权限                           |
| `/settings/permissions`  | 角色权限                   | 配置管理权限                           |
| `/settings/menus`        | 菜单页面                   | 配置管理权限                           |
| 其他地址                 | 404                        | 提供返回工作台入口                     |

路由生成继续使用现有 Vue Router 文件路由插件。`pages` 文件路径和现有 URL 保持兼容，没有手动改写 `typed-router.d.ts`、路由生成配置或启动守卫。菜单分组是展示分组，动态页面标识属于服务端配置，不把任意菜单名称拼接成新路由层级。

`navigation/paths.ts` 只提供跳转地址与地址生成函数，不注册路由。活动标识、动态页面标识统一编码；配置中心页签与概览卡片共用 `navigation/settings.ts`，避免维护两份模块目录。PC 和 H5 导航共用去重、地址和激活规则。活动详情返回和删除成功后返回，均按当前账号授权菜单寻找活动列表；缺少列表入口时返回首页。

`components/layout/navigation.ts` 保留两个原有函数的转导出，兼容既有校验引用；新的业务代码统一从 `@/navigation` 导入。

## 3. 动态页面白名单

`views/workspace/view-registry.ts` 用 `Record<PageComponent, Component>` 对内置视图做完整类型检查：工作台、活动列表、发起活动、待办、档案、配置概览、领导看板。所有动态视图按需加载，待办与档案明确传入各自范围。旧配置中心动态地址仍可进入统一配置入口。

禁止把服务端组件码直接作为文件路径执行任意动态导入。未知组件码（包括对象原型属性名）显示明确空态；组件资源加载失败显示重载提示。

`use-workspace-page.ts` 随页面标识变化重新请求授权。请求开始清空旧页面，只接受最新响应，403 或其他失败不继续显示旧内容；离开页面后不再写入状态。

## 4. 活动详情分工

- `views/activities/ActivityDetailPage.vue`：负责布局、数据传递、抽屉和业务区域的连接。
- `views/activities/use-activity-detail.ts`：负责详情加载、请求时序、历史版本选择、上传资格、编辑与办理状态、导航。切换活动时重置旧活动的抽屉、任务及编辑状态。
- `components/activity/detail/ActivityApplicationSection.vue`：展示当前或历史申请的字段、预算、负责人及版本选择。
- `components/activity/detail/ActivityExecutionSection.vue`：展示执行安排、执行汇报、成果归档与阶段附件。
- `components/activity/detail/ActivityHistoryPanel.vue`：展示流程办理进度和操作记录，通过事件通知父页面办理任务。
- `components/activity/detail/use-activity-presentation.ts`：集中处理历史快照、动态字段分组、金额受限与格式化。

业务动作继续依赖服务端返回的 `actions`；字段、节点材料、附件和评价仍使用原有权限与接口。拆分后保留历史快照的脱敏展示和只读办理限制。

## 5. 接口归属

| 模块                   | 接口职责                                                     |
| ---------------------- | ------------------------------------------------------------ |
| `api/auth.ts`          | 登录、会话、退出、修改密码                                   |
| `api/activities.ts`    | 活动分页、导出、详情、草稿、提交、业务动作、结构调整、软删除 |
| `api/workflow.ts`      | 任务审批、转交、兼容路线预览                                 |
| `api/workspace.ts`     | 动态页面授权、授权成员目录                                   |
| `api/configuration.ts` | 配置草案、发布、成员密码管理                                 |
| `api/files.ts`         | 阶段附件上传、附件权限                                       |
| `api/notifications.ts` | 站内消息、已读                                               |
| `api/templates.ts`     | 流程模板及活动类型，沿用现有封装                             |
| `api/insights.ts`      | 活动评价与领导看板，沿用现有封装                             |
| `api/http.ts`          | 同源请求、CSRF、统一错误、幂等重试                           |

接口函数名称、参数、请求路径、请求方法与重试语义保持兼容。业务模块从具体文件导入。`api/index.ts` 仅转导出原有接口，便于既有调用兼容，不继续承载实现。

## 6. 后续开发约束

1. 路由文件保持薄入口，原则上不超过 40 行；加载、保存、审批编排放视图或模块 hook。
2. 新页面按自动路由目录约定创建文件；不要手动修改生成文件或路由声明。
3. 新增内置动态页面类型时同步扩展领域类型、服务端校验与本地视图白名单，服务端始终负责授权。
4. 跳转使用 `@/navigation`，不要散落拼接动态标识，也不要指向不存在的 `/activities` 列表地址。
5. 跨目录导入使用 `@/`，同目录使用 `./`；新增 Vue 文件统一 `script setup lang="tsx"`。
6. 业务状态优先使用 `ref` / `computed`；新增与修改的函数必须有中文 JSDoc。
7. 保留模块边界，较大的业务区域按职责拆分，避免为了目录整齐而给简单页面增加多层包装。

## 7. 静态检查与局部回归

```sh
pnpm --filter @workflow/web check:structure
pnpm --filter @workflow/web typecheck
```

`check:structure` 不构建或启动项目。它检查页面入口长度、TSX 脚本、跨目录别名和导入方向，防止业务逻辑重新堆入路由入口。类型检查覆盖白名单完整性、组件 props、接口参数和文件路由参数。

本次局部校验使用模拟响应，覆盖以下情形：

- 动态页面先后切换但旧请求后到，仍保留新页面；403 后清空旧视图，可以重试；卸载后忽略响应。
- 三类列表分别传入工单、待办、档案范围；7 类组件码完整，未知码与原型属性不渲染。
- 配置中心去重，页签与概览目录一致，动态标识正确编码，返回地址符合授权菜单。
- 当前与历史快照切换，受限预算与负责人展示保持原有语义。
- 草稿版本、模板版本、CSRF、导出范围、删除原因、附件网络重试幂等键保持一致。

本次未启动项目、构建、浏览器预览或执行端到端测试。
